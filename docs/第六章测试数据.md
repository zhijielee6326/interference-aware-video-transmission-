测试内容：

- 验证JPEG质量、FEC冗余和帧率随策略等级切换。

测试命令：

```bash

```

| 策略等级 | JPEG质量 | FEC冗余 | FPS | 说明 |
| --- | ---: | ---: | ---: | --- |
| none | 85 | 1 | 25 | 无干扰，高质量传输 |

## 6.6 USRP实时可视化长测

本轮采用实时图形化界面进行长时间测试，而不是短突发分类脚本。可视化界面包含实时PSD、CCNN七分类概率、I/Q时域波形和JSR准确率曲线四个面板。

测试命令：

```bash
cd /home/zhijielee/桌面/毕设/gnuradio
/home/zhijielee/桌面/毕设/venv/bin/python3 run_system_with_viz.py --mode full --duration 120
```

120秒长测结果如下：

| 指标 | 原始full流程 | 优化后仪表盘流程 |
| --- | ---: | ---: |
| 测试时长 | 120 s | 120 s |
| 发送帧数 | 483 | 482 |
| 接收处理块数 | 609 | 823 |
| CCNN处理样本数 | 121,800,000 | 164,600,000 |
| 检测到干扰次数 | 605 | 816 |
| 策略切换次数 | 7 | 18 |
| 最终策略 | 轻度干扰 - 降质保传 | 轻度干扰 - 降质保传 |

优化说明：`run_system_with_viz.py` 调用 `VideoTransmissionSystem(no_gui=True)` 时，实时仪表盘只需要PSD、I/Q和CCNN概率状态，不需要完整视频解调和JPEG解码。因此在 `video_transmission_system.py` 的USRP接收线程中，针对 `no_gui=True` 路径跳过视频解码，仅保留RF监测和CCNN推理，使120秒内接收处理块数由609提升至823。

测试现象：UHD控制台仍出现接收overflow标记，说明当前Python实现仍存在“连续收流”和“每块CCNN推理”同线程竞争的问题。该问题影响实时采样连续性，但不代表模型离线准确率或历史JSR扫描准确率下降。后续工程优化可将USRP采集和CCNN推理拆成独立线程/队列，或降低实时推理频率以进一步减少overflow。

## 6.7 结论记录

测试结果表明，仿真模式下视频传输链路能够完成发送、信道注入、接收、干扰识别和策略切换闭环；CCNN模型在离线生成样本上实现70/70正确识别；自适应控制器与论文描述的8帧干扰确认、3帧等级确认、12帧恢复逻辑一致。USRP B210实机可以被UHD正常识别，并能运行120秒实时图形化可视化界面，完成PSD、CCNN概率、I/Q波形和策略状态的连续刷新。论文中应采用历史USRP JSR扫描和本轮full模式长测作为硬件验证依据，不应将短突发无同步脚本的临时结果作为最终准确率结论。
